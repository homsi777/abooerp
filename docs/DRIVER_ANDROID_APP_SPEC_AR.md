# مواصفات تطبيق Android لتتبّع السائق - شركة عبو المحمود

هذا الملف مخصص لإرساله إلى Gemini Studio أو أي فريق/أداة ستبني تطبيق Android منفصل للسائق. يُبنى هذا التطبيق في مشروع منفصل تماماً عن مشروع abooerp الرئيسي، لكنه يتصل بنفس الـ backend عبر API فقط.

المطلوب تطبيق Android بسيط جداً مخصص للسائق فقط: تسجيل دخول، عرض رحلته الحالية وأسطر شحناتها، وإرسال موقعه (GPS) للخادم بشكل دوري أثناء الرحلة ليظهر على خريطة "خريطة شحنات" داخل النظام الرئيسي. هذا التطبيق **لا** يدير شحنات ولا أموالاً ولا صلاحيات أخرى.

## 1. الهدف العام

بناء تطبيق Android يفتحه السائق قبل انطلاق رحلته، يسجّل دخوله باسم مستخدم وكلمة مرور خاصين به، يرى فيه بيانات رحلته الحالية (الوجهات وأسطر الشحنات التي يحملها)، ويضغط زر "بدء تتبّع الرحلة" فيرسل التطبيق موقعه كل دقيقة إلى دقيقتين للخادم طوال الرحلة — حتى لو أغلق الشاشة أو وضع الهاتف في جيبه — إلى أن يضغط "إنهاء الرحلة" أو يسجّل خروجه.

## 2. المعمارية المطلوبة

المسار الصحيح:

```text
Flutter Android App
        ↓ HTTPS
Backend API على VPS (نفس مشروع abooerp)
        ↓
PostgreSQL
```

ممنوع أن يتصل تطبيق Android مباشرة بقاعدة البيانات. كل العمليات يجب أن تمر عبر الـ backend الحالي:

```text
https://www.abooerp.org/api/v1
```

## 3. نوع التطبيق المقترح

يُفضَّل Flutter (نفس أسلوب تطبيق الوكيل الموجود مسبقاً في هذا المشروع — راجع `AGENT_ANDROID_APP_SPEC_AR.md` لنفس القواعد العامة).

المتطلبات التقنية:

- Flutter stable، Dart null safety.
- RTL عربي بالكامل.
- Android فقط في النسخة الأولى (لا iOS الآن).
- تخزين التوكنات بشكل آمن (secure storage / EncryptedSharedPreferences).
- HTTP client مثل Dio.
- State management بسيط (Riverpod أو Provider).
- **حزمة تتبّع موقع خلفية حقيقية** — مثل `flutter_background_geolocation` أو توليفة `geolocator` + `flutter_foreground_task`. الشرط الأساسي: يجب أن تستمر خدمة الموقع بالعمل كخدمة أمامية (Foreground Service) حتى لو أُغلقت الشاشة أو قُفل الهاتف، مع إشعار دائم ظاهر (هذا شرط أندرويد نفسه لحماية الخصوصية، لا يمكن تجاوزه ولا إخفاؤه).

ممنوع بناء التطبيق كـ WebView للنظام الحالي. المطلوب تطبيق موبايل حقيقي بواجهات Flutter.

## 4. المستخدم المستهدف

المستخدم هو السائق فقط.

كل سائق يرى فقط:

- بياناته الشخصية (اسمه، رقم رخصته إن عُرض).
- رحلته الحالية النشطة وأسطر شحناتها.

لا يرى:

- رحلات/شحنات سائقين آخرين.
- أي بيانات مالية (رواتب، سلف، صناديق).
- إعدادات النظام أو بيانات الإدارة.

## 5. تسجيل الدخول

الشاشة الأولى:

- شعار الشركة في الأعلى (ملف الشعار: `company-logo.png`، دائري بخلفية بيضاء، ألوان أخضر غامق وذهبي — يُطلَب من صاحبة المشروع).
- اسم الشركة بالعربية: **شركة عبو المحمود للنقل والخدمات اللوجستية**.
- حقل اسم المستخدم.
- حقل كلمة المرور.
- زر "تسجيل الدخول".
- رسالة خطأ واضحة بالعربية عند فشل الدخول (اسم مستخدم/كلمة مرور خاطئة، أو لا يوجد اتصال).

بعد نجاح تسجيل الدخول:

- حفظ accessToken و refreshToken في secure storage.
- الانتقال مباشرة إلى شاشة "رحلتي الحالية".

## 6. المصادقة والتوكنات

```http
POST /api/v1/auth/login
POST /api/v1/auth/refresh
GET  /api/v1/auth/me
```

Payload تسجيل الدخول:

```json
{
  "username": "driver_omar",
  "password": "password"
}
```

شكل الاستجابة (موجود فعلياً في الخادم):

```json
{
  "success": true,
  "data": {
    "user": {
      "id": "uuid",
      "username": "driver_omar",
      "role": "driver_mobile",
      "permissions": ["driver.trip.read", "driver.location.write"],
      "userType": "employee",
      "companyId": "uuid",
      "branchId": "uuid-or-null",
      "driverId": "uuid"
    },
    "session": {
      "accessToken": "jwt...",
      "refreshToken": "hex...",
      "tokenType": "Bearer",
      "expiresIn": 900
    }
  }
}
```

ملاحظات مهمة:

- التطبيق يرسل `Authorization: Bearer ACCESS_TOKEN` في كل طلب محمي.
- عند انتهاء صلاحية accessToken (كل 15 دقيقة تقريباً) يُستخدم `/auth/refresh` تلقائياً دون إزعاج السائق.
- عند فشل refresh يتم تسجيل الخروج وإيقاف خدمة تتبّع الموقع فوراً.
- `driverId` هو الحقل الذي يربط حساب الدخول بسجل السائق الفعلي (سيُضاف للخادم — انظر القسم 23).

## 7. مشكلة Device Authorization

المشروع الحالي يملك منطق device authorization مخصص لشبكة LAN/Electron، لا علاقة له بتطبيق موبايل على الإنترنت.

**الحل الموجود فعلاً وجاهز للاستخدام مباشرة:** يرسل التطبيق ترويسة ثابتة في **كل طلب** (ليس فقط تسجيل الدخول):

```http
X-Client-Type: mobile
```

هذا يكفي ليتجاوز الخادم طلب تسجيل الجهاز (`x-device-id`) بالكامل. لا حاجة لأي منطق إضافي.

## 8. الأذونات المطلوبة (مهم جداً)

يجب أن يطلب التطبيق، بترتيب واضح ومشروح للسائق قبل كل طلب (لماذا نحتاج هذا الإذن):

1. **الإشعارات** (`POST_NOTIFICATIONS` — أندرويد 13 فما فوق): ضرورية لإظهار إشعار "جارٍ تتبّع الرحلة" أثناء العمل.
2. **الموقع أثناء الاستخدام** (`ACCESS_FINE_LOCATION`): يُطلب أولاً، خطوة أساسية.
3. **الموقع طوال الوقت/بالخلفية** (`ACCESS_BACKGROUND_LOCATION`): يُطلب في خطوة ثانية منفصلة بعد منح الإذن الأول (أندرويد يفرض هذا الترتيب بخطوتين، لا يمكن طلبهما معاً)، مع توجيه السائق إلى إعدادات النظام إن لزم.
4. **خدمة أمامية بنوع موقع** (`FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION` — إلزامي من أندرويد 14).

اشرحي للسائق داخل التطبيق (قبل طلب كل إذن) لماذا تحتاجينه بجملة عربية بسيطة، لأن أندرويد يرفض الإذن تلقائياً إن شعر المستخدم أنه غير مبرَّر.

## 9. شاشة "رحلتي الحالية"

بعد الدخول، الشاشة الرئيسية الوحيدة تقريباً:

- اسم السائق.
- رقم الرحلة/التاريخ.
- نقطة الانطلاق والوجهات المخطَّطة (مثال: حلب ← الرقة ← الحسكة ← القامشلي).
- عدد أسطر الشحنات في هذه الرحلة.
- زر كبير واضح: **"بدء تتبّع الرحلة"** (يتحوّل إلى "إيقاف التتبّع — إنهاء الرحلة" بعد الضغط).
- مؤشر حالة واضح (نقطة خضراء نابضة + "التتبّع نشط") عندما تعمل الخدمة.

Endpoint مطلوب بناؤه (انظر القسم 23):

```http
GET /api/v1/driver/current-trip
```

## 10. قائمة أسطر الشحنات

أسفل شاشة الرحلة، قائمة بطاقات (وليس جدولاً) لكل شحنة ضمن هذه الرحلة:

- رقم الإيصال.
- المرسل / المستلم.
- الوجهة (المدينة/المحافظة).
- عدد الطرود أو الوزن.
- الحالة الحالية (مثال: بانتظار التسليم / جارٍ النقل).

هذه القائمة **للعرض فقط** في النسخة الأولى — لا أزرار تغيير حالة، ولا طباعة، ولا تعديل.

## 11. خدمة تتبّع الموقع في الخلفية

هذا هو جوهر التطبيق:

- عند الضغط على "بدء تتبّع الرحلة"، تبدأ خدمة أمامية (Foreground Service) حقيقية مع إشعار دائم ثابت لا يمكن إخفاؤه (مثال: "عبو المحمود — جارٍ تتبّع رحلتك").
- الخدمة تستمر بالعمل حتى لو:
  - أُغلقت الشاشة.
  - انتقل السائق لتطبيق آخر.
  - قُفل الهاتف (طالما البطارية لم تُطفئ التطبيق قسراً — نبّهي السائق لاستثناء التطبيق من "تحسين البطارية" في إعدادات أندرويد).
- الخدمة تتوقف فقط عند:
  - الضغط على "إنهاء الرحلة" من داخل التطبيق.
  - تسجيل الخروج.

## 12. إرسال نبضات الموقع (Location Ping)

كل 60–120 ثانية (قابل للتعديل)، يرسل التطبيق نبضة موقع للخادم:

```http
POST /api/v1/driver/location-ping
Authorization: Bearer ACCESS_TOKEN
X-Client-Type: mobile
Content-Type: application/json
```

```json
{
  "lat": 36.2021,
  "lng": 37.1343,
  "accuracyM": 15,
  "recordedAt": "2026-10-18T14:32:00Z",
  "tripId": "uuid-من-current-trip"
}
```

الاستجابة المتوقعة:

```json
{ "success": true }
```

### طابور محلي عند انقطاع الشبكة (مهم جداً)

الطرق بين حلب والرقة/الحسكة/القامشلي قد تفقد التغطية. يجب:

- تخزين كل نبضة موقع محلياً (قاعدة بيانات محلية بسيطة مثل sqflite أو Hive) إن فشل الإرسال.
- عند عودة الاتصال، إرسال كل النبضات المتراكمة بالترتيب (دفعة واحدة أو واحدة تلو الأخرى).
- لا تُفقَد أي نقطة موقع بسبب انقطاع مؤقت للإنترنت.

## 13. بدء/إنهاء الرحلة صراحة

عند الضغط على "بدء تتبّع الرحلة":

```http
POST /api/v1/driver/trip/start
Authorization: Bearer ACCESS_TOKEN
```

```json
{ "tripId": "uuid" }
```

عند الضغط على "إنهاء الرحلة":

```http
POST /api/v1/driver/trip/end
Authorization: Bearer ACCESS_TOKEN
```

```json
{ "tripId": "uuid" }
```

هذا يسمح لشاشة "خريطة شحنات" في النظام الرئيسي بمعرفة متى بدأ السائق فعلياً ومتى انتهى، بدل الاعتماد فقط على توقيت أول/آخر نبضة موقع.

## 14. الأمان

- لا تخزين لكلمة المرور، فقط التوكنات.
- استخدام secure storage حصراً للتوكنات.
- عدم إرسال أي بيانات موقع قبل تسجيل الدخول والضغط الصريح على "بدء تتبّع الرحلة" — الخصوصية مهمة، السائق يجب أن يتحكم بمتى يبدأ التتبّع.
- إيقاف الخدمة وحذف أي نبضات معلّقة محلياً فور تسجيل الخروج.

## 15. التعامل مع الأخطاء

- فشل تسجيل الدخول: رسالة عربية واضحة.
- رفض إذن الموقع: شاشة تشرح أن التطبيق لا يعمل بدونه، مع زر يفتح إعدادات النظام مباشرة.
- انقطاع الإنترنت أثناء التتبّع: لا توقف الخدمة، فقط خزّني النبضات محلياً (القسم 12) واستمري بالمحاولة.
- فشل تجديد التوكن: تسجيل خروج تلقائي + إيقاف التتبّع + رسالة "انتهت الجلسة، سجّلي الدخول مجدداً".

## 16. التصميم وتجربة المستخدم

- عربي RTL بالكامل.
- شاشتان أساسيتان فقط (تسجيل دخول + رحلتي الحالية) — بساطة قصوى، السائق يستخدم التطبيق أثناء القيادة فيجب ألا يحتاج تفكيراً.
- أزرار كبيرة، خط واضح، تباين ألوان عالٍ (يُستخدَم أحياناً تحت ضوء الشمس المباشر).
- ألوان الشعار: أخضر غامق (#0f172a أو قريب منه) وذهبي، مطابقة لهوية الشركة البصرية.

## 19. Endpoints الجديدة المطلوب بناؤها في الخادم (ستُبنى بنفس هذا الشكل بالضبط)

هذه غير موجودة بعد في مشروع abooerp، وستُبنى لاحقاً من فريق الخادم بنفس العقد (contract) الموضَّح هنا بالضبط، حتى يعمل تطبيق Android دون أي تعديل لاحق:

```http
GET  /api/v1/driver/current-trip
POST /api/v1/driver/trip/start
POST /api/v1/driver/trip/end
POST /api/v1/driver/location-ping
```

بالإضافة إلى تعديل داخلي في الخادم (لا يخص تطبيق Android، فقط للعلم): إضافة دور جديد `driver_mobile` وربط حساب تسجيل الدخول بسجل السائق (`driverId` في استجابة تسجيل الدخول، القسم 6).

## 20. قاعدة مهمة جداً

التطبيق يعتمد على الخادم في كل شيء: تحديد السائق، تحديد رحلته، تحديد شحناته. **التطبيق لا يخزّن ولا يحسب أي بيانات شحنات أو رحلات بنفسه** — فقط يعرض ما يرسله الخادم، ويرسل الموقع.

## 21. MVP المطلوب للنسخة الأولى

النسخة الأولى يجب أن تحتوي فقط:

1. Login.
2. شاشة رحلتي الحالية (معلومات الرحلة + قائمة الشحنات للعرض فقط).
3. بدء/إيقاف تتبّع الموقع (خدمة خلفية حقيقية + إشعار دائم).
4. إرسال نبضات الموقع مع طابور محلي عند الانقطاع.
5. Logout.

لا تضف في MVP:

- أي تعديل على بيانات الشحنات.
- أي بيانات مالية.
- خرائط داخل تطبيق السائق نفسه (الخريطة تظهر في النظام الرئيسي، ليس هنا).
- إشعارات push من الخادم (لاحقاً إن لزم).

## 22. ترتيب التنفيذ المقترح

1. إنشاء مشروع Flutter.
2. إعداد API client (Dio) + secure storage.
3. بناء Login وربطه بـ `/auth/login`.
4. بناء شاشة رحلتي الحالية (بيانات تجريبية ثابتة مبدئياً قبل جهوزية endpoint الخادم).
5. دمج خدمة الموقع الخلفية (Foreground Service + إشعار دائم) واختبارها بمفردها أولاً (بدون خادم).
6. ربط بدء/إنهاء الرحلة ونبضات الموقع بالخادم بعد جهوزية endpoints القسم 19.
7. بناء طابور التخزين المحلي للنبضات عند انقطاع الشبكة.
8. اختبار على جهاز أندرويد حقيقي في منطقة ضعيفة التغطية فعلياً (محاكاة طريق صحراوي).
9. اختبار كامل عبر VPS على HTTPS.

## 23. اختبارات القبول

يُعتبر التطبيق جاهزاً عندما:

- يسجّل سائق الدخول بنجاح، ويُمنع أي مستخدم آخر غير مرتبط بسائق.
- تظهر رحلة هذا السائق وشحناته فقط.
- يبدأ التتبّع فعلياً بإشعار دائم ظاهر.
- تستمر نبضات الموقع بالوصول للخادم حتى مع إغلاق الشاشة لمدة 10 دقائق على الأقل (اختبار فعلي).
- عند قطع الإنترنت لعدة دقائق ثم إعادته، تصل كل النبضات المتراكمة دون فقدان.
- يتوقف التتبّع فوراً عند "إنهاء الرحلة" أو تسجيل الخروج.
- يعمل refresh token تلقائياً دون انقطاع الجلسة.
- يعمل التطبيق على جهاز أندرويد حقيقي عبر VPS/HTTPS.

## 24. ملاحظات مهمة للمطور

- لا تستخدم WebView.
- لا تبنِ تطبيقاً إدارياً كاملاً — ركّز على السائق فقط: دخول، عرض رحلة، تتبّع موقع.
- كل النصوص عربية RTL.
- اشرحي كل طلب إذن بجملة بسيطة قبل طلبه من النظام.
- اختبري استهلاك البطارية فعلياً — التتبّع كل دقيقة لعدة ساعات يجب ألا يُفرغ البطارية بسرعة غير مقبولة (استخدمي دقة موقع متوسطة balanced، لا أعلى دقة ممكنة، إلا إذا احتجنا ذلك لاحقاً).
- أظهري حالة الاتصال بوضوح (متصل / النبضات تُخزَّن محلياً بانتظار الاتصال).

## 25. Prompt مختصر يمكن إرساله إلى Gemini Studio

ابنِ تطبيق Flutter Android باسم `AbooERP Driver` مخصص للسائقين فقط. التطبيق عربي RTL بشاشتين أساسيتين: تسجيل دخول (اسم مستخدم/كلمة مرور، شعار الشركة)، وشاشة "رحلتي الحالية" تعرض بيانات الرحلة وقائمة أسطر الشحنات (للعرض فقط)، مع زر كبير "بدء تتبّع الرحلة" يشغّل خدمة أمامية حقيقية (Foreground Service) مع إشعار دائم، ترسل موقع GPS كل دقيقة إلى دقيقتين للخادم عبر `POST /api/v1/driver/location-ping` حتى مع إغلاق الشاشة، وتخزّن النبضات محلياً (sqflite أو Hive) عند انقطاع الإنترنت وترسلها لاحقاً دفعة واحدة. استخدم JWT (`Authorization: Bearer`) مع تجديد تلقائي عبر `/auth/refresh`، وأرسل ترويسة `X-Client-Type: mobile` في كل طلب. اطلب أذونات الموقع (أثناء الاستخدام ثم الخلفية بخطوتين منفصلتين كما يفرض أندرويد) والإشعارات بوضوح مع شرح كل إذن. لا تستخدم WebView، ولا تضف أي ميزات إدارية أو مالية. استخدم secure storage للتوكنات، وDio للطلبات، وAPI base قابلاً للتغيير بين dev وprod (الإنتاج: `https://www.abooerp.org/api/v1`).
